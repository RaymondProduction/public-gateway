# Перевірки Public Gateway 0.2.0

Дата: 7 жовтня 2026 року. Середовище: ноутбук розробника з Linux 7.0, Docker Engine 29.8, Compose v5.5, Python 3.14; модуль `wireguard` доступний у ядрі.

## Не виконано

Запуск на реальному VPS користувача не виконувався: handshake через інтернет, UDP через провайдерський firewall, випуск HTTPS-сертифіката для справжнього домену, поведінка після перезавантаження ОС VPS і відновлення backup не перевірялися. Розділ «Прокинуті порти» у вебінтерфейсі перевірений лише тим, що сторінка рендериться; сам сценарій не автоматизовано. Вебінтерфейс перевірявся автоматизованим сценарієм у headless Chrome і скриншотами, не вручну в різних браузерах; кнопки «Завантажити» та «Скопіювати» не перевірялися. Скрипт `scripts/connect-client.sh` перевірений лише синтаксично (`bash -n`): його запуск потребує systemd і root на клієнтському пристрої. Клієнти Windows/macOS/Android/iOS, навантажувальні тести та незалежний аудит безпеки не проводили.

## Перевірка після розгортання на VPS

Виконай `docker compose up -d --build --wait`, `docker compose ps`, підключи ноутбук через `scripts/connect-client.sh`, запусти демопрограму на VPN-адресі й перевір `POST /peers/laptop/check`. Після цього перевір зовнішній HTTP-тест за IP, а далі HTTPS зі справжнім доменом. Прибери HTTP-маршрут після перевірки HTTPS.

До використання реальних даних перевір відкликання тестового ключа, відсутність зовнішнього доступу до порту 2019, перезапуск VPS, збереження ключів/сертифікатів і відновлення backup. Виріши, чи залишати API на `0.0.0.0` по HTTP, чи обмежити `API_BIND=127.0.0.1` і працювати через SSH-тунель.
